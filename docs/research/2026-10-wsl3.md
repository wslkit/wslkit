# WSL 3.0: a cgroup namespace per distribution

Written 2026-10-05, on WSL **3.0.1** (kernel 6.18.40.1), Windows 10 22H2, the
day the stable channel moved from 2.7.14 to 3.0.1. The change itself shipped
in the 2.9.13 pre-release.

On 3.0.1 `wslkit top` fell back to the process method and said "this WSL has
no per-distribution cgroup", and `wslkit limit show` and `set` refused with
"Ubuntu has no cgroup of its own". Both were wrong: the cgroup is still there,
seen from a different place.

## What changed

microsoft/WSL#41512, "Create new namespaces for distro cgroups", 2.9.13. Its
stated reason is compatibility: rootless docker and nerdctl assume a fixed
systemd cgroup layout. Security was not the reason. The same PR moves a systemd
distribution's init from `wsl-user/distro-N/systemd` to `wsl-user/distro-N`,
puts every process of a distribution without systemd in `non-systemd`, and
forces cgroup v2 whenever distribution isolation is on.

## Measured

Ubuntu (systemd), skrog-engine (no systemd, util-linux), and a throwaway Alpine
3.24 minirootfs (busybox only, then with `util-linux-misc`).

- **`/proc/self/cgroup` says `0::/non-systemd`.** Nothing names
  `/wsl-user/distro-N` from inside. `/proc/1/cgroup` says `0::/init.scope`
  under systemd.
- **`/sys/fs/cgroup` is the distribution's own cgroup.** Its mountinfo root is
  `/`, it has `memory.current`, `memory.high`, `cpu.max` and the rest, and its
  children are the distribution's own (`system.slice`, `init.scope`,
  `non-systemd`, or `docker` in skrog-engine). The real root cgroup has no
  `memory.current`, which is how the two layouts are told apart.
- **The VM's root and `wsl-user/non-distro` are out of sight.** `wsl --system`
  joins the same namespace and sees the same thing.
- **Writes from inside fail.** The mount is `nsdelegate`, and the kernel
  refuses writes to a namespace root's interface files from inside it:
  `printf max > /sys/fs/cgroup/memory.high` gives `I/O error`, as root.
- **WSL's own init for the distribution is outside the namespace.**
  `init`, `init-systemd(Ubuntu)` and `init-watcher` are in the initial cgroup
  namespace and visible from inside. A shell's parent chain reaches one:
  `sh` → `Relay` → `SessionLeader` → `init-systemd(Ubuntu)` (pid 2, with
  systemd as pid 1 still inside), or → `init(skrog-engine)` (pid 1).
  `nsenter -t <that pid> -C` then sees `0::/wsl-user/distro-13799/non-systemd`,
  and a write through it to `/sys/fs/cgroup/memory.high` succeeds: tried with
  the value already there, in Ubuntu and in skrog-engine, then for real with
  `wslkit limit set --high 3GB --cpus 1.5` and read back from the kernel.
- **busybox's `nsenter` has no `-C`.** Alpine 3.24's is BusyBox v1.37.0 and
  rejects it; `util-linux-misc` provides one that works.
- **`boot.command` can apply a limit.** In Alpine without systemd, a boot
  command writing through `nsenter -t <ancestor> -C` had the limit in place
  about half a second after start. Not measured under systemd.

Measuring this needs care: `wsl.exe -d X -- sh -c '...$(...)...'` hands the
whole command line to the distribution's login shell, which expands `$(...)`
once before `sh` runs. A sampling loop written that way prints the same
instant six times. Use `--exec`, or send the script on stdin.

## Two other 2.9.13 changes that were measured

- **wsl.conf skips a bad line** (microsoft/WSL#41606). Line 2 not a setting,
  `hostname=wkprobe` below it: WSL prints `Expected '=' in /etc/wsl.conf:2` and
  the hostname applies. Up to 2.9.12 it stopped reading at the bad line.
- **`automount.cgroups=v1` is overridden** while isolation is on: WSL prints
  `Cgroup v1 is incompatible with per-distribution cgroup isolation. Using
  cgroup v2 instead.` and mounts cgroup2.

## What wslkit does now

- `top` reads the namespace root as the distribution's cgroup and names it by
  asking WSL's init through `nsenter`, or `/` where that is not possible. It
  prints no group rows inside a namespace, because there they would be the
  distribution's own children counted a second time.
- `limit` reads there too, and writes through `nsenter -t <ancestor> -C`. Where
  there is no `nsenter` with `-C`, `limit set` says so and what to install.
- WSL006 reports every bad wsl.conf line on 2.9.13 and newer, each costing only
  itself.
