# WSL 3.0: a cgroup namespace per distribution

Written 2026-10-05, on WSL **3.0.1** (kernel 6.18.40.1), Windows 10 22H2, the
day the stable channel moved from 2.7.14 to 3.0.1. The change itself shipped
in the 2.9.13 pre-release.

On 3.0.1 `wslkit top` fell back to the process method and said "this WSL has
no per-distribution cgroup", and `wslkit limit show` and `set` refused with
"Ubuntu has no cgroup of its own". Both were wrong: the cgroup is still there,
seen from a different place.

## What changed

microsoft/WSL#41512, "Create new namespaces for distro cgroups", 2.9.13. Its
stated reason is compatibility: rootless docker and nerdctl assume a fixed
systemd cgroup layout. Security was not the reason. The same PR moves a systemd
distribution's init from `wsl-user/distro-N/systemd` to `wsl-user/distro-N`,
puts every process of a distribution without systemd in `non-systemd`, and
forces cgroup v2 whenever distribution isolation is on.

## Measured

Ubuntu (systemd), skrog-engine (no systemd, util-linux), and a throwaway Alpine
3.24 minirootfs (busybox only, then with `util-linux-misc`).

- **`/proc/self/cgroup` says `0::/non-systemd`.** Nothing names
  `/wsl-user/distro-N` from inside. `/proc/1/cgroup` says `0::/init.scope`
  under systemd.
- **`/sys/fs/cgroup` is the distribution's own cgroup.** Its mountinfo root is
  `/`, it has `memory.current`, `memory.high`, `cpu.max` and the rest, and its
  children are the distribution's own (`system.slice`, `init.scope`,
  `non-systemd`, or `docker` in skrog-engine). The real root cgroup has no
  `memory.current`, which is how the two layouts are told apart.
- **The VM's root and `wsl-user/non-distro` are out of sight.** `wsl --system`
  joins the same namespace and sees the same thing.
- **Writes from inside fail.** The mount is `nsdelegate`, and the kernel
  refuses writes to a namespace root's interface files from inside it:
  `printf max > /sys/fs/cgroup/memory.high` gives `I/O error`, as root.
- **WSL's own init for the distribution is outside the namespace.**
  `init`, `init-systemd(Ubuntu)` and `init-watcher` are in the initial cgroup
  namespace and visible from inside. A shell's parent chain reaches one:
  `sh` → `Relay` → `SessionLeader` → `init-systemd(Ubuntu)` (pid 2, with
  systemd as pid 1 still inside), or → `init(skrog-engine)` (pid 1).
  `nsenter -t <that pid> -C` then sees `0::/wsl-user/distro-13799/non-systemd`,
  and a write through it to `/sys/fs/cgroup/memory.high` succeeds: tried with
  the value already there, in Ubuntu and in skrog-engine, then for real with
  `wslkit limit set --high 3GB --cpus 1.5` and read back from the kernel.
- **busybox's `nsenter` has no `-C`.** Alpine 3.24's is BusyBox v1.37.0 and
  rejects it; `util-linux-misc` provides one that works.
- **`boot.command` can apply a limit.** In Alpine without systemd, a boot
  command writing through `nsenter -t <ancestor> -C` had the limit in place
  about half a second after start. Not measured under systemd.

Measuring this needs care: `wsl.exe -d X -- sh -c '...$(...)...'` hands the
whole command line to the distribution's login shell, which expands `$(...)`
once before `sh` runs. A sampling loop written that way prints the same
instant six times. Use `--exec`, or send the script on stdin.

## Two other 2.9.13 changes that were measured

- **wsl.conf skips a bad line** (microsoft/WSL#41606). Line 2 not a setting,
  `hostname=wkprobe` below it: WSL prints `Expected '=' in /etc/wsl.conf:2` and
  the hostname applies. Up to 2.9.12 it stopped reading at the bad line.
- **`automount.cgroups=v1` is overridden** while isolation is on: WSL prints
  `Cgroup v1 is incompatible with per-distribution cgroup isolation. Using
  cgroup v2 instead.` and mounts cgroup2.

## What wslkit does now

- `top` reads the namespace root as the distribution's cgroup and names it by
  asking WSL's init through `nsenter`, or `/` where that is not possible. It
  prints no group rows inside a namespace, because there they would be the
  distribution's own children counted a second time.
- `limit` reads there too, and writes through `nsenter -t <ancestor> -C`. Where
  there is no `nsenter` with `-C`, `limit set` says so and what to install.
- WSL006 reports every bad wsl.conf line on 2.9.13 and newer, each costing only
  itself.

Fixtures: `internal/top/testdata/wsl-3.0.1-*.txt`, captured with
`wslkit top --raw`.

## Not done

The "WSL itself" and `/docker` rows `top` showed on 2.9.8 to 2.9.12 would
need a fresh cgroup2 mount from outside the namespace, in a private mount
namespace. Not tried.

# 3.0.2 to 3.0.4

Written 2026-10-25, on WSL **3.0.3** (kernel 6.18.54.1), Windows 10 22H2.
3.0.3 has been the stable release since 2026-10-09; 3.0.4 is a pre-release
from 2026-10-20. Read from the release notes, the 80 most-discussed
microsoft/WSL issues opened since 3.0.1, the PRs behind them, and the 3.0.3
and 3.0.4 source. **Measured** marks what was run on this machine; the rest
is read from source or from the threads.

## What changed that wslkit depends on

- **New disks are readable only by their owner** (3.0.2,
  microsoft/WSL#41678). **Measured:** a distribution imported on 3.0.3 gets
  `D:PAI(A;;FA;;;BA)(A;;FA;;;<user>)(A;;FA;;;<VM SID>)(A;;FA;;;<capability
  SID>)`. A disk copied the ordinary way takes its folder's permissions
  instead; on this machine `D:\` gives Everyone full control by inheritance.
  `disk move` and `disk snapshot` now copy a protected list (#120).
- **`wsl --list --running --quiet` with nothing running exits 0 and prints
  nothing.** **Measured.** Without `--quiet` it exits -1 and says so
  (`WslClient.cpp`). So output cut short, as in microsoft/WSL#41937, where
  security software ended wsl.exe before it flushed, looks exactly like "none".
- **binfmt_misc is the kernel's, shared by every distribution.** WSL
  registers `WSLInterop` when the VM boots, and shadows the `status` file in
  systemd distributions so that one shutting down cannot clear the table for
  the rest (`ProtectBinfmtStatus`). **Measured:** a handler for `MZ`
  registered by hand after WSL's made `cmd.exe` run under its interpreter on
  3.0.3; removing it brought interop back. `BIN001` (#121).
- **Nested virtualization can vanish without a word.** WSL drops it when the
  host's capability query fails, and said nothing up to 3.0.3. KB5127648 (the
  October 2026 update, builds ending `.9711`) makes that query fail on AMD
  (microsoft/WSL#41917); 3.0.4 prints a warning (#41942). Not measurable
  here: WSL never offers nested virtualization on Windows 10. `KVM001` (#121).
- **Mirrored networking reserves 4096 contiguous ports**, and up to 3.0.3 a
  refusal leaves the VM with no network (`0x8007054f`). 3.0.4 halves the
  request down to 512 (#41880). How HNS picks the run is undocumented; the
  report behind the fix traced the refusal to WinNAT's exclusions fragmenting
  the dynamic range (#41812). `NET005` measures that (#121).
- **`sparseVhd` is honoured again** from 3.0.2, marked experimental
  (#41726). From 2.5.6 to 3.0.1 it was ignored, with "Sparse VHD support is
  currently disabled due to potential data corruption". `--set-sparse true`
  no longer needs `--allow-unsafe`. WSL005 now says which applies.
- **Before 3.0.4, `virtiofs=true`, `networkingMode=consomme` or an explicit
  `experimental.swiotlb` put `swiotlb=force` on the kernel command line**,
  which sends all disk DMA through the small default bounce pool; under load,
  "swiotlb buffer is full" (#41828, fixed by #41829). WSL005 warns.
- **No `.wslconfig` key was added or removed** between the table's previous
  source (2026-09-12) and 3.0.4: `tools/gen-wslconfig-keys` against the 3.0.4
  checkout changed only the source stamp.
- **Kernel headers** are mounted at `/lib/modules/$(uname -r)/build` from
  3.0.2 (#41400). The bundled `perf` that came with them was removed again in
  3.0.4 (#41904), after it shadowed distribution packages (#41934).

## Kernel 6.18 dropped options people use

Not wslkit's to fix, and nothing checks for them yet. Each is an open issue
asking for the option back:

- `CONFIG_TASKSTATS`: `/proc/<pid>/io` is gone, and Apache brpc programs
  such as Typesense crash at start (#41847, #41825). A WSL maintainer asked
  for it back in the next kernel. `wslkit top` does not read it (it reads
  `io.stat` and `/proc/<pid>/stat`).
- `CONFIG_PPP`: openfortivpn and pppd stop working (#41750).
- `CONFIG_INET_DIAG_DESTROY`, `CONFIG_INET_RAW_DIAG`: `ss -K` and raw-socket
  listings (#41984).

## Open on 3.0.3, no fix released

- New sessions fail with `Wsl/Service/WSAETIMEDOUT` (`0x8007274c`) while
  open ones keep working (#42029, #42006); a contributor reproduced a guest
  VMBus deadlock that could cause it. `doctor explain` covers it (#120).
- `wsl --shutdown` waits the whole `initTimeout` under systemd (#41852);
  fixed in 3.0.4 by reaping child processes at shutdown (#41899).

## Not done

- A guest check for the kernel options above: it would read
  `/proc/config.gz` through the VM facts script, but there is no wslkit
  feature it would explain yet.

## Found while measuring

- **A failed start holds the disk for about a minute.** **Measured:** after a
  start that fails, the disk stays open for 61 to 75 seconds, with or
  without `wsl --terminate`, and can be neither deleted nor renamed. `disk
  move`'s rollback tried at once, so it left the copy behind, or, for a
  rename, pointed the distribution back at a file that had not moved back.
  It now waits, as `compact` does.
- **One stream, two encodings.** **Measured:** stderr from a command that
  fails in the guest is wsl.exe's own warning in UTF-16LE followed by the
  guest's UTF-8. wslkit decoded the whole stream as one or the other, so half
  of every such error came out as CJK characters. `internal/wslout` decodes
  it line by line, and the five copies of the old decoder are gone.
